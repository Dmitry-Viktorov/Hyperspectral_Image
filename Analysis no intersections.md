# Почему в отчете нулевые пересечения метаданных

## Пояснение:

Нулевые пересечения между `.nc`, `.tif` и `.rsp` в текущем отчете — это ожидаемый результат для строгого буквального сравнения ключей и значений, а не ошибка скрипта.

## Сравнивается

В проекте используется нормализованное **exact-match** сравнение:

1. Ключи метаданных (`name`, `units`, `long_name`, и т.д.)
2. Значения метаданных (строки и числовые значения после нормализации)

Сравнение выполняется для пар:

1. `NC <-> RSP`
2. `NC <-> TIFF`
3. `TIFF <-> RSP`
4. `NC <-> TIFF <-> RSP`

## Почему пересечений нет

### 1. Разные модели метаданных

- NetCDF (`.nc`) хранит научные атрибуты массива (`radiance`, `wavelength`, `fwhm`, `units`, `standard_name` и др.).
- GeoTIFF (`.tif`) хранит в основном растровые/драйверные поля (`driver`, `size`, `projection`, `geotransform`, `WAVELENGTH_COUNT`, band metadata).
- RSP (`.rsp`) — это паспорт/телеметрия с другой иерархией тегов и служебными параметрами.

Эти форматы семантически связаны, но их названия полей обычно не совпадают дословно.

### 2. Строгое сравнение без словаря соответствий

Скрипт не использует словарь синонимов вида:

- `wavelength_count` ↔ `количество каналов`
- `long_name` ↔ `description`
- `units` ↔ специализированные поля паспорта

Без такого слоя соответствий даже «похожие по смыслу» поля дают 0 при exact-match.

### 3. Разный уровень детализации

- В `.nc` много спектрально-научных атрибутов.
- В `.tif` сохраняется ограниченный набор метаданных после экспорта.
- В `.rsp` присутствует большой объем аппаратно-временной телеметрии.

Из-за этого пересечение по значениям также обычно равно нулю.

## Почему это важно для отчета

Нулевой результат тоже является валидным аналитическим выводом:

1. Сравнение отработало корректно.
2. Показано, что прямое сопоставление форматов без семантического маппинга недостаточно.
3. Это обосновывает следующий шаг: добавить правила соответствия и «мягкое» сравнение.

## Что можно улучшить дальше

1. Добавить словарь соответствий терминов между `.nc`, `.tif`, `.rsp`.
2. Сравнивать не только ключи, но и производные признаки:
   - количество каналов,
   - min/max длины волны,
   - наличие/отсутствие геопривязки,
   - единицы измерения после нормализации.
3. Добавить fuzzy/alias matching и отдельную таблицу «семантических совпадений».

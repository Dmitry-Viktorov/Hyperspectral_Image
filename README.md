# Проект по гиперспектральным данным 

## 1. Цель работы

Сделать полный учебный конвейер для гиперспектрального изображения:

1. прочитать гиперспектральный куб из NetCDF (`.nc`),
2. экспортировать его в многополосный GeoTIFF (`.tif`),
3. собрать и проанализировать метаданные,
4. сравнить метаданные между тремя источниками:
	1. NetCDF (`.nc`),
	2. GeoTIFF (`.tif`),
	3. паспортные файлы (`.rsp`).

## 2. Что реализовано в проекте

Скрипт [unpack_hyperspectral.py](unpack_hyperspectral.py) выполняет:

1. Загрузку файла [dataset/AV320241005t175313_005_L1B_RDN_f6524bfe_RDN.nc](dataset/AV320241005t175313_005_L1B_RDN_f6524bfe_RDN.nc) из группы `radiance`.
2. Экспорт гиперспектрального куба в [dataset/AV320241005t175313_005_L1B_RDN_f6524bfe_RDN.tif](dataset/AV320241005t175313_005_L1B_RDN_f6524bfe_RDN.tif).
3. Сохранение графика одной полосы и спектра пикселя в папку [reports](reports).
4. Создание детального отчёта [reports/metadata_report.txt](reports/metadata_report.txt).
5. Создание краткого отчёта [reports/metadata_summary.txt](reports/metadata_summary.txt).
6. Сравнение метаданных `.nc/.tif/.rsp`, включая попарные и общие пересечения.

## 3. Структура папок

1. [dataset](dataset): исходные и рабочие данные (`.nc`, `.tif`, `.rsp`).
2. [reports](reports): отчёты и визуализации.
3. [unpack_hyperspectral.py](unpack_hyperspectral.py): основной код.
4. [requirements.txt](requirements.txt): зависимости.
5. [FINAL_REPORT.md](FINAL_REPORT.md): итоговый отчёт по проекту.

## 4. Зависимости и установка

Требуемый Python: `3.13.x` (рекомендуется то же окружение, в котором выполнялась работа).

Установка:

```powershell
pip install -r requirements.txt
```

Если GDAL не ставится через `pip`, используйте локальное колесо:

```powershell
pip install gdal-3.12.2-cp313-cp313-win_amd64.whl
```

## 5. Как запускать проект

Полный запуск:

```powershell
python unpack_hyperspectral.py
```

Быстрый запуск для анализа (без повторного экспорта TIFF и без графиков):

```powershell
python unpack_hyperspectral.py --no-tiff --no-plot
```

Полезные флаги:

1. `--no-tiff`: не пересоздавать TIFF.
2. `--no-plot`: не строить графики.
3. `--no-report`: не писать детальный отчёт.
4. `--no-summary`: не писать краткий отчёт.
5. `--output-tiff <путь>`: изменить путь выходного TIFF.
6. `--report-file <путь>`: изменить путь детального отчёта.
7. `--summary-file <путь>`: изменить путь краткого отчёта.

## 7. Логика сравнения метаданных

В проекте реализованы три уровня пересечений:

1. `NC <-> RSP`: прямые совпадения по нормализованным ключам и значениям.
2. `NC <-> TIFF`: что сохранилось/дошло до TIFF после экспорта.
3. `TIFF <-> RSP`: что совпадает между выходным растром и паспортом.
4. `NC <-> TIFF <-> RSP`: общие пересечения сразу всех трёх источников.

Нормализация нужна для честного сравнения:

1. перевод в нижний регистр,
2. удаление лишних символов,
3. унификация строковых представлений значений.

## 8. Ограничения и пояснения

1. Если в NetCDF отсутствуют CRS/геопривязка, они не появятся автоматически в TIFF.
2. Формат `.rsp` может сильно отличаться по терминологии от NetCDF, поэтому нулевые точные пересечения допустимы.
3. Для больших данных экспорт TIFF может занимать значимое время.
